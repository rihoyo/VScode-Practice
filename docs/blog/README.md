# 블로그 기록 가이드 (티스토리)

가이드 홈페이지(`guide/`)의 내용을 티스토리 블로그에 올릴 때 쓰는 규칙이다. 마스터가 **"티스토리 블로그에 올리게 디자인된 마크다운 형식으로 만들어줘"**와 유사하게 요청하면 이 문서와 [_template.md](_template.md)를 따라 만든다.

## 원칙

- **원문은 `guide/*.html` 하나뿐이다.** 블로그용 마크다운은 요청이 있을 때 원문에서 뽑아 만들고, 두 곳을 동시에 고치지 않는다.
- 요청받은 부분만 만든다. 페이지 전체를 옮기지 않는다. 예: `git.html#git-path`, `vscode.html#claude-code`
- 설명문은 홈페이지와 같은 `~다.` 문체를 쓴다.
- 마스터가 직접 확인한 단계만 완료로 쓴다. 확인 전 내용은 `> 📌 확인 전 안내` 로 표시한다.

## 만드는 순서

1. 마스터가 지정한 원문 위치(파일과 `#id`)를 읽는다.
2. [_template.md](_template.md)를 복사해 `docs/blog/YYYY-MM-DD-주제.md` 로 저장한다.
3. 아래 변환표대로 HTML 요소를 마크다운으로 바꾼다.
4. 상대 링크(`git.html#git-path`)는 블로그에서 열리지 않으므로 풀어서 쓴다. 같은 시리즈 글이면 글 제목으로, 아니면 링크를 지운다.
5. 마지막 체크리스트를 확인하고, 마스터가 티스토리에 붙여 넣어 렌더링을 확인한다.

## HTML → 마크다운 변환표

| 원문(HTML) | 블로그(마크다운) |
| --- | --- |
| `<h2>` 섹션 제목 | `## 제목` |
| `<h3>` 소제목 | `### 제목` |
| `<details><summary>` | `### 제목` (접기는 쓰지 않고 소제목으로 펼친다) |
| `<ol>` 단계 | `1.` 번호 목록. 단계마다 **굵은 글씨** 동작 → 결과 순서로 쓴다 |
| `<ul>` | `-` 목록 |
| `<p class="note">` | `> 💡 내용` 인용문 |
| `<kbd>Ctrl</kbd>` | `` `Ctrl` + `S` `` |
| `<code>` | `` `코드` `` |
| 여러 줄 명령 | ` ```bash ` 코드 블록 |
| `<table>` | 마크다운 표 (열은 4개 이하로 줄인다) |
| 화면 캡처 | `![설명](파일명.png)` 자리만 표시하고, 실제 이미지는 마스터가 티스토리에 올린다 |
| 기술 연결 지도 | 지도는 움직이는 화면이므로 옮기지 않는다. 연결 한 줄 요약만 표로 쓴다 |

## 티스토리 표시 규칙

- 제목은 `#` 하나만 쓴다. 본문 소제목은 `##`부터 시작한다.
- 한 문단은 3문장 이내로 끊는다.
- 이모지는 문단 머리표로만 쓴다. 허용: 💡 참고, ⚠️ 주의, ✅ 확인, 📌 안내.
- 표와 코드 블록 앞뒤에는 빈 줄을 둔다.
- 티스토리 마크다운 렌더링은 테마마다 다를 수 있다. 처음 올린 뒤 깨지는 문법이 있으면 이 문서를 고친다.

## 글 하나의 구성 (템플릿 요약)

1. 한 줄 요약
2. 이 글에서 하는 일 (목표와 결과물)
3. 준비물
4. 단계 (번호 목록, 화면에서 누를 것 → 성공하면 보이는 것)
5. 막혔을 때
6. 다음 글

## 체크리스트

- [ ] 원문 위치(파일과 `#id`)를 확인했다
- [ ] 문체가 `~다.` 로 통일됐다
- [ ] 상대 링크가 남아 있지 않다
- [ ] 마스터가 확인하지 않은 단계는 `확인 전`으로 표시했다
- [ ] 개인정보(이메일, 사내 주소, 사번)가 없다

## 홈페이지 원문을 쓸 때의 규칙 (미래의 변환을 쉽게 하기 위해)

- 섹션에는 항상 `id`를 단다. 변환 요청의 기준 주소가 된다.
- 단계는 `<ol>`, 참고는 `<p class="note">`, 단축키는 `<kbd>`, 명령은 `<code>`로만 표시한다. 색이나 글자 크기로 의미를 나타내지 않는다.
- 같은 제목을 반복하지 않는다. 연속된 항목은 `1.`, `2.` 번호로 구분한다.
- 표는 단순한 행과 열로만 만든다. 병합 셀은 쓰지 않는다.
