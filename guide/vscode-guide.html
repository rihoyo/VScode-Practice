세 도구는 이렇게 연결된다

Clone · GitHub → 회사 PC
VS Code에서 복제를 누르면 Git이 GitHub 저장소의 파일과 이력을 가져온다.
저장 → Commit → Push · 회사 PC → GitHub
VS Code로 파일을 저장한다. Git으로 버전을 기록하고, 그 버전을 GitHub에 올린다.
Pull · GitHub → 집 PC
집 PC에 이미 복제해 둔 저장소를 열고, GitHub의 새 커밋을 받아 이어서 작업한다.

이후에 다룰 수업

  • Git · 변경 내용 비교, 브랜치로 실험하기, 충돌 읽기, 워크트리로 동시 작업하기
  • GitHub · 커밋 기록 찾기, 다른 PC에서 동기화하기, 변경 검토하기
  • VS Code · 프로젝트 폴더와 프로필, Codex·Claude 인계, Figma MCP 연결
  • Claude Code · 확장과 터미널 방식 비교, 네이티브 설치와 npm 설치의 차이
  • Node.js · npm으로 도구 설치하기, 이 지도처럼 npm 패키지를 가져다 쓰는 법
이 기록을 직접 갱신하는 법

새 실습을 추가할 때는 제목과 함께 어느 도구에서 누르는지, 파일이 어디로 움직이는지, 성공하면 무엇이 보이는지를 기록한다. 해당 도구의 목차에서 실습으로 링크하고, 확인한 단계만 완료로 표시한다. 브라우저에서 새로고침해 본 뒤 커밋과 푸시를 하면 집에서도 갱신된 기록을 받을 수 있다.

지도에 새 기술을 추가하는 법

guide/map-data.js의 NODES에 기술(처음 위치·색·설명)을, EDGES에 연결(오가는 것·이유·방법·성공 신호·애니메이션 단계)을 한 덩어리씩 추가한다. 위치는 대략만 주어도 물리 엔진이 알아서 정리한다. 직접 확인한 연결만 status: 'done'으로 바꾼다.

VS Code 터미널에서 cd tools로 이동한 뒤 npm run check를 실행하면 오타, 빠진 항목, 깨진 링크, 문체 오류를 찾아 준다. 검사 통과가 나오면 브라우저를 새로고침한다.

집 PC에서 지도가 움직이지 않으면

지도는 guide/vendor/d3.min.js를 읽는다. 이 파일은 저장소에 함께 올라가므로 보통 Pull만 하면 된다. 파일이 없다는 메시지가 나오면 tools 폴더에서 npm install 다음 npm run build를 실행한다.
