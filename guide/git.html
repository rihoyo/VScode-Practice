Git과 커밋

Git은 파일의 변경 이력을 기록하는 도구다. VS Code의 소스 제어에서 커밋하고 GitHub에 푸시할 수 있다.

커밋은 이름표를 붙인 대본 버전이다. 대본.md에 오프닝을 쓰고 Ctrl + S를 누르면 편집 중인 파일이 저장된다. 소스 제어에서 파일 옆 +를 누르고 30초 대본 초안 완성이라는 메시지로 커밋하면, 그때 고른 변경이 Git 기록에 남는다. 다음 날 오프닝을 바꿔 다시 커밋하면 두 버전을 비교하거나 이전 문장을 찾아 되살릴 수 있다. Push를 하면 기록한 버전을 GitHub에 올려 집에서도 받아볼 수 있다.

1. 부가 기능 · Select Components

Git과 함께 설치할 부가 기능을 고르는 화면이다. Git 2.56.1 실습 화면에서는 현재 체크 그대로 Next를 눌러도 된다. 이번 VS Code 실습에 아래 부가 기능은 모두 선택 사항이다.

  • Additional icons → On the Desktop · 바탕화면에 바로가기를 추가한다.
  • Windows Explorer integration · 파일 탐색기 우클릭 메뉴에 Git Bash(명령창)와 Git GUI(별도 화면)를 여는 항목을 추가한다.
  • Git LFS · 큰 바이너리 파일을 별도 저장소로 관리하는 기능이다. 이 옵션만 체크해도 큰 파일이 자동으로 올라가지는 않는다.
  • Associate .git* · 연결 대상 Git 설정 파일을 기본 텍스트 편집기로 연다.
  • Associate .sh · 셸 스크립트 파일을 Bash로 실행하도록 연결한다.
  • Check daily · Git for Windows 업데이트를 매일 확인한다.
  • Add a Git Bash Profile to Windows Terminal · Windows Terminal에 Git Bash를 열 수 있는 프로필을 추가한다.
  • Scalar · 규모가 큰 Git 저장소를 효율적으로 관리하는 도구다.

화면 아래 342.4 MB는 현재 선택에 필요한 최소 디스크 공간이다.

2. 기본 편집기

Git이 커밋 메시지 등을 입력받아야 할 때 열 편집기를 고르는 화면이다. 이 실습에서는 Use Visual Studio Code as Git's default editor를 선택하고 Next를 누른다.

예를 들어 터미널에서 메시지 없이 git commit을 실행하면 Git이 이 편집기를 연다. VS Code 소스 제어의 메시지 칸에 직접 입력해 커밋하면 보통 별도 편집기가 열리지 않는다. Vim과 Nano는 터미널에서 쓰는 편집기이고, VS Code Insiders는 별도로 설치하는 미리보기 버전이다.

3. 첫 브랜치 이름

브랜치는 작업 이력이 이어지는 줄기다. 이 화면은 PC에서 새 저장소를 만들 때(git init) 첫 줄기에 붙일 이름을 정한다.

Let Git decide를 고르면 이 설치 화면 기준으로 master가 쓰인다. 이번 실습에서는 두 번째 Override the default branch name for new repositories를 선택하고 입력칸의 main을 그대로 둔 뒤 Next를 누른다.

GitHub의 vscode-practice를 복제할 때는 저장소에 이미 설정된 브랜치를 가져온다. 기존 저장소의 브랜치 이름은 그대로다.

4. PATH 설정

PATH는 Windows에서 프로그램을 찾을 때 확인하는 폴더 목록이다. 이미 선택된 두 번째 Git from the command line and also from 3rd-party software를 그대로 두고 Next를 누른다. PowerShell과 VS Code에서 Git을 찾을 수 있게 해 주는 권장 옵션이다.

  • 첫 번째는 Git Bash에서만 Git 명령을 쓸 수 있게 설정한다.
  • 세 번째는 Git과 함께 Unix 명령도 PATH에 추가한다. Windows의 find, sort보다 같은 이름의 Unix 명령이 먼저 실행될 수 있다.

설치 후 인식 확인은 12단계에서 한다.

5. SSH 프로그램

두 옵션 모두 SSH 접속에 쓰는 OpenSSH다. 차이는 Git이 어느 위치의 ssh.exe를 실행하느냐다.

  • Use bundled OpenSSH · Git for Windows가 함께 설치하는 OpenSSH를 사용한다. 이번 실습에서는 이 기본값을 두고 Next를 누른다.
  • Use external OpenSSH · Windows 기본 제공 OpenSSH처럼 PC에 별도로 설치되어 있고 PATH에서 찾을 수 있는 ssh.exe를 사용한다.

GitHub 주소가 git@github.com:…이면 SSH 프로그램을 사용한다. 이번 실습의 https://github.com/… 주소는 HTTPS로 연결하므로 이 설정의 영향을 받지 않는다.

6. HTTPS 연결 방식

GitHub에 HTTPS로 연결할 때 서버 인증서를 어떤 방식으로 확인할지 정하는 화면이다. 회사 PC에서는 이미 선택된 두 번째 Use the native Windows Secure Channel library를 두고 Next를 누른다.

  • OpenSSL · Git과 함께 제공되는 ca-bundle.crt 파일의 인증서 목록을 사용한다.
  • Windows Secure Channel · Windows 인증서 저장소를 사용한다. 회사가 여기에 배포한 내부 인증서도 사용할 수 있다.

OpenSSL 옵션의 ca-bundle.crt는 Git 설치 폴더 쪽에 있는 인증서 목록이다. 프로젝트 폴더에 인증서를 만들거나 커밋하는 설정이 아니다. Windows 정품 인증 여부만으로 두 옵션을 고를 필요는 없다. 회사 인증서가 Windows에 배포돼 있다면 Windows Secure Channel을 쓰면 된다.

이번 실습은 HTTPS 주소로 복제하므로 이 설정이 적용된다. GitHub 계정 로그인은 복제 과정에서 별도로 진행한다.

7. 줄바꿈 방식

CRLF는 Windows에서 흔한 줄바꿈 형식이고, LF는 Linux·macOS에서 흔한 형식이다. 이번 Windows 실습에서는 이미 선택된 첫 번째 옵션을 두고 Next를 누른다.

  • 첫 번째 · Git이 작업 폴더에 꺼낸 텍스트는 CRLF로, 커밋에 기록할 텍스트는 LF로 맞춘다.
  • 두 번째 · 꺼낼 때는 저장소의 형식을 유지하고, 커밋할 때 CRLF를 LF로 바꾼다.
  • 세 번째 · 이 설정으로는 양쪽 모두 자동 변환하지 않는다.

프로젝트가 .gitattributes로 파일별 줄바꿈 규칙을 정했다면 그 규칙이 우선한다.

8. Git Bash 창

Git Bash를 별도로 실행할 때 명령을 입력할 창을 고르는 화면이다. 이미 선택된 첫 번째 Use MinTTY 그대로 Next를 누른다.

  • MinTTY · Git Bash의 기본 터미널 창이다. 창 크기를 조절하고 한글 같은 유니코드 문자를 표시할 수 있다.
  • Windows 기본 콘솔 · Git Bash를 Windows 콘솔 창에서 실행한다. 대화형 Python처럼 Windows 콘솔과 직접 상호작용하는 프로그램을 Git Bash에서 자주 실행할 때 고려할 수 있다.

VS Code의 소스 제어와 VS Code 안에서 여는 PowerShell은 각자의 기존 설정을 사용한다.

9. Pull 기본 동작

Pull은 GitHub에서 새 커밋을 받아 현재 브랜치에 반영하는 동작이다. 이번 실습은 이미 선택된 Merge를 두고 Next를 누른다. 예를 들어 회사에서 푸시한 뒤 집에서 처음 작업을 시작한다면, 집에 별도 커밋이 없을 때는 최신 커밋까지 그대로 따라간다. 이를 fast-forward라고 한다.

회사에서 푸시하기 전에 집에서도 별도 커밋을 만들면 양쪽 이력이 갈라질 수 있다. 그때 옵션의 차이가 드러난다.

  • Merge · 양쪽 커밋을 유지하고 합친 결과를 새 커밋으로 기록한다.
  • Rebase · 내 로컬 커밋을 GitHub 최신 커밋 위에 다시 적용한다. 다시 적용된 커밋은 식별자가 바뀐다.
  • Fast-forward only · 최신 커밋까지 그대로 따라갈 수 있을 때만 반영한다. 이력이 갈라졌다면 멈춘다.

Merge나 Rebase 중 같은 부분을 다르게 수정했다면 충돌을 해결해야 할 수 있다. 회사와 집을 오갈 때는 작업 시작 전에 Pull, 마치면 Commit 후 Push를 한다.

10. 로그인 도우미

이번 실습은 HTTPS로 비공개 GitHub 저장소에 접속하므로 첫 번째 Git Credential Manager를 그대로 두고 Next를 누른다. 인증이 필요할 때 브라우저 로그인을 돕고, Windows 자격 증명 관리자에 인증 정보를 보관해 다음 접속에 재사용한다.

None을 고르면 이 로그인 도우미를 설정하지 않는다. SSH만 쓰거나 별도 인증 수단을 이미 마련한 경우에 쓰는 선택이다. 이 인증 정보는 PC의 자격 증명 저장소에 보관되며 프로젝트 파일이나 커밋에 포함되지 않는다.

11. 추가 옵션

Enable file system caching은 체크하고 Enable symbolic links는 해제한 상태로 Install을 누른다.

  • 파일 시스템 캐시 · Git이 파일 정보를 메모리에 잠시 보관해 일부 작업을 빠르게 처리한다.
  • 심볼릭 링크 · 다른 파일이나 폴더를 가리키는 경로다. Windows에서 만들려면 권한이 필요하고, 이번 HTML 실습에는 쓸 일이 없다.
12. 설치 완료와 VS Code 인식 확인

Launch Git Bash는 설치를 닫으면서 Git Bash 창을 한 번 여는 옵션이다. VS Code로 실습할 것이므로 체크를 해제하고 Finish를 누른다.

VS Code는 설치된 git.exe를 찾아 소스 제어에서 상태 확인, 복제, 커밋 등을 할 때 실행한다. Git Bash 창을 열어둘 필요는 없다.

  1. 설치 때 추가한 PATH를 반영하려면 VS Code 창을 모두 닫았다가 다시 연다.
  2. 터미널 → 새 터미널에서 git --version을 실행한다. 버전 번호가 나오면 Git을 찾은 것이다.
  3. 소스 제어에서 리포지토리 복제를 눌러 복제 단계로 넘어간다.
