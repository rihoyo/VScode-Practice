03

주소와 서브넷 계산

IPv4 주소는 32비트이고, CIDR 표기의 /n은 앞의 n비트가 네트워크 부분이라는 뜻이다. 남는 호스트 부분이 32 − n비트이므로 주소 개수와 장비에 쓰는 주소 개수는 다음과 같다.

전체 주소 = 232 − n   ·   장비에 쓰는 주소 = 232 − n − 2

네트워크 주소와 브로드캐스트 주소는 장비에 줄 수 없어 2개를 뺀다. 아래 칸에 주소를 넣으면 계산 결과와 32비트 구조가 바로 보인다.

04

온프레미스 구조

  • 접근 · 분배 · 코어의 3계층으로 스위치를 나누는 구성이 전통적이다.
  • VLAN으로 같은 스위치 안에서도 네트워크를 논리적으로 나눈다.
  • 방화벽과 DMZ로 외부에 공개하는 서버와 내부 서버를 분리한다.

06

하이브리드 연결

온프레미스와 클라우드를 잇는 방식은 크게 두 가지다. 사이트 간 VPN은 인터넷 위에 암호화된 터널을 만들어 빠르게 구축하고, 전용선은 통신사 회선으로 대역폭과 지연을 안정적으로 확보한다. 경로 정보 교환에는 보통 BGP를 쓴다.

그림 6-1 · 하이브리드 연결 구성

07

설계 순서

  1. 요구사항 사용자 수, 서비스 위치, 가용성 목표, 예산을 정리한다.
  2. IP 계획 온프레미스와 클라우드의 대역이 겹치지 않아야 나중에 연결할 수 있다.
  3. 서브넷 분리 공개 영역, 내부 영역, 데이터 영역으로 나눈다.
  4. 연결 방식 VPN과 전용선, 이중화 여부를 고른다.
  5. 보안과 점검 규칙을 적용하고 장애 상황을 가정해 확인한다.
