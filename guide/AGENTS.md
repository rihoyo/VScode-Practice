# guide 에이전트

「나의 개발 스텝」 홈페이지(`guide/`)와 Node.js 도구(`tools/`)를 맡아. 이 두 폴더 밖은 고치지 마.

- `guide/vscode-guide.html`에서 진행 상태를 확인해. 개념과 실습은 `git.html`, `github.html`, `vscode.html`에 기록하고, 다른 도구의 개념을 참조할 때는 해당 항목으로 링크해. 드롭다운(머리말 왼쪽 위, 스크롤하면 위쪽 고정 메뉴바 왼쪽)은 서로 다른 메인 페이지(VS Code 공부·리눅스·네트워크)로 이동하는 용도고, 개요·Git·GitHub·VS Code 같은 사이트 안 메뉴는 머리말 탭과 고정 메뉴바 탭에 둬. 현재 페이지 목차는 오른쪽에 둬.
- **설명문은 `~다.` 문체로 써.** 대화는 평소 말투를 유지하되 이 폴더 안의 문장과 지도 데이터는 `~다.`로 끝내. 같은 제목을 반복하지 말고 연속 항목은 `1.`, `2.` 번호로 구분해. 섹션에는 항상 `id`를 달아.
- 새 기술이나 연결을 배우면 `data/map-data.js`의 `NODES`와 `EDGES`에 추가해 개요의 기술 연결 지도에 반영해. 마스터가 확인한 연결만 `status: 'done'`으로 표시해.
- 고친 뒤에는 `tools` 폴더에서 `npm run check`를 실행해. 링크, 문체, 폰트, 지도 데이터, 에이전트 목록의 경로를 검사해 줘.
- VS Code 공부 세트의 디자인은 다크 모드 개발자 느낌이고, 모서리는 모든 페이지에서 각지게 해. 폰트는 고딕만 써. 바탕·명조 계열은 금지고, 모노스페이스 스택에도 한글 고딕 폴백을 넣어.
- 홈페이지는 서버 없이 브라우저에서 로컬 HTML로 열려야 해. 외부 라이브러리는 완성 파일을 `vendor/`에 커밋해 둬.
- **메인 페이지(사이트)는 색만이 아니라 레이아웃까지 새로 디자인해.** VS Code 공부 세트는 `assets/vscode/guide.css`, 리눅스는 `assets/linux/linux.css`·`linux-viz.js`(근흑 바탕·인광 초록·모서리 괄호 패널·스캔 뷰포트), 네트워크는 `assets/network/network.css`·`network-field.js`(전면 실시간 관계 그래프 위의 밝은 기술 문서)를 쓰고, 새 메인 페이지는 자기 CSS를 따로 만들어. 공용 메뉴 스타일은 `assets/shared/site-ui.css`가 맡고 색은 각 CSS의 변수로 정해.
- **등록**: 새 메인 페이지는 `data/sites.js`의 `sites`에, 메인 페이지 안의 새 페이지는 해당 사이트의 `pages`에 추가해. 머리말에 `<div class="sitenav">`를 두고 목차에 `data-toc`와 링크별 `data-tags`를 달아. 그다음 `tools`에서 `npm run build`로 키워드 색인을 다시 만들어. 낡으면 `npm run check`가 알려 줘.
- 키워드 검색은 머리말 오른쪽의 `키워드 검색` 버튼(누르면 입력칸 + 이 페이지 태그·전체 태그, 입력하면 관련 키워드·섹션을 바로 표시)과 고정 메뉴바 검색칸이 같은 패널을 쓰고, 옆에 `전체 키워드` 버튼을 둬. 목차 칸에는 입력칸 없이 그 페이지의 태그 토글만 둬. 고정 메뉴바 표시는 `site-nav.js`가 모든 페이지에서 맡아.
- **리눅스 계열 모드**: `linux.html`은 `<html data-mode>`(mix·deb·rh)로 색과 내용을 바꿔. 내용은 `data-m="deb mix"`처럼 보일 모드를 적어 두고, 색은 `linux.css`의 `:root[data-mode]` 변수가 정해. 전환 스위치는 `assets/shared/site-nav.js`가 머리말과 고정 메뉴바에 넣고, 연출은 `assets/linux/linux-mode.js`(0.45초 안)가 맡아. 새 리눅스 내용은 두 계열 모두 `data-m`으로 나눠 써.
- **주석(기준·출처·작은 보충)**: 본문 흐름을 끊는 부가 설명(기준일, 읽은 출처와 범위, 확인 전, 메뉴 이름이 바뀔 수 있다는 단서, 수치가 달라 보이는 이유)은 본문에 길게 쓰지 말고 주석으로 단다. 본문 자리에는 `<sup class="fn" data-fn="이름"></sup>`만 두고, 페이지 맨 끝(main 안)에 `<section class="notes" id="notes"><h2>주석</h2><ol><li data-fn="이름">내용~다.</li></ol></section>`을 둬. 번호는 본문 차례대로 `glossary.js`가 매기고(손으로 쓰지 마), 같은 이름을 여러 곳에 쓰면 같은 번호가 붙어. 번호에 마우스를 올리면 용어 설명창처럼 내용이 뜨고, 짝이 안 맞으면 `npm run check`가 알려 줘. 목차에 `<a href="#notes" data-tags="주석">주석</a>`을 넣어. 주석은 어느 부·장에도 속하지 않는 별도 항목이라 목차에서도 구분선을 두고 따로 보여. 목차 이동은 부드러운 스크롤 없이 바로 점프해(`scroll-behavior:auto`, JS에도 `behavior: smooth`를 쓰지 마). 학습에 꼭 필요한 정보는 주석에 숨기지 말고 본문에 둬. 본문 번호는 문장 우측 상단의 작은 위첨자 n(점 없음)으로 통일하고 색만 테마마다 달라: `--fn` 변수를 각 테마 CSS(`guide.css`, `guide-ui.css`의 키워드, `ai.css`, `linux.css`, `network.css`)에 두고 새 메인 페이지는 자기 CSS에 정해. `.notes` 목록은 단계 번호 상자를 이어받지 않게 되돌려 뒀어. 마우스 감지 범위는 `sup.fn::after`로 숫자보다 넓게 잡고, 설명창에는 `주석 n` 제목 없이 내용만 띄워.
- **그림 연출과 셸 편집**: 설명용 그림은 라이브러리 없이 HTML·CSS 상자와 WAAPI로 만들고, 애니메이션 완료 신호는 시간 제한과 함께 기다려(숨은 탭에서 멈추지 않게). 클릭 판정은 `button[data-x]`처럼 요소를 좁혀(바깥 상자의 같은 속성에 걸리지 않게). 역슬래시가 든 경로를 셸로 고칠 때는 sed 대신 node를 써(GNU sed는 `\U`를 대문자 명령으로 읽어).
- **새 내용 작업 절차**: ① 자리: 마스터가 요청한 순서가 아니라 학습 흐름으로 정해. 시작 튜토리얼은 맨 앞, 전제가 되는 것은 앞, 그 위에 쌓이는 것은 하위나 뒤, 드문 고급 주제는 맨 뒤야. 기존 장의 하위인지 먼저 따지고(예: 권한 분리는 Organization 하위), 재배치하면 목차·장 번호·장 사이 링크를 같이 고쳐. 장이 많은 페이지는 대분류(부)로 묶어: 새 내용은 먼저 어느 부인지 정하고 없으면 부를 만들어(목차 `<span class="part">`, 본문 `<div class="part-head">`). 부가 있는 페이지의 장 제목은 `n.`이 아니라 `부-순서`(1-1, 1-2, 2-1)로 쓰고 장 사이 링크도 `4-1장`처럼 적어. 제목은 목차와 본문에서 줄이 넘어가지 않게 짧게 지어(장·소제목·접이식 제목 모두). 한 상황에만 대응하는 내용은 장을 늘리지 말고 장 안의 접이식 항목에 넣어. ② 사실: 공식 문서와 요금 페이지를 직접 읽고 쓰고, 못 읽은 값은 추측하지 말고 "확인 전" 또는 "적혀 있지 않다"로 밝혀(위 주석으로). ③ 마무리: 목차 항목과 `data-tags`, 필요한 용어를 사전에, `tools`에서 `npm run build`와 `npm run check` 통과, `STATUS.md`의 해당 영역 줄 고치기. ④ 보고: 화면을 직접 찍거나 열어 본 것만 "확인했다"고 하고(목록, 표, 주석까지), 마스터가 실제 화면에서 확인한 것만 완료로 표시해.
- **용어 설명창**: 용어는 `data/glossary/*.json`에 항목(`match`, `name`, `say`, `full`, `literal`, `desc`)으로 등록해. `match`는 찾을 글자, `say`는 한글 발음, 줄임말이면 `full`(풀네임)과 `literal`(직역)가 꼭 필요하고, `desc`는 `~다.` 한 줄 뜻이야. 고친 뒤 `npm run build`로 `data/generated/glossary-data.js`를 다시 만들어. 칸이 비거나 겹치면 `npm run check`가 알려 줘. 엔진은 `assets/shared/glossary.js`고 데이터는 거기 두지 마. 본문에서는 용어를 길게 풀어 쓰지 말고 용어 중심으로 짧게 써.

## 폴더 구조 (어디를 고치면 되나)

```
guide/
├─ *.html                 글 내용 층. 페이지마다 한 파일. 목차(data-toc, data-tags)와 본문
├─ assets/                화면을 만드는 코드 층
│  ├─ shared/             모든 페이지 공용: site-ui.css(메뉴·검색 패널), glossary.css/js(설명창), cursor.css/js(마우스 포인터), site-nav.js, keywords.js
│  ├─ vscode/             VS Code 공부 세트: guide.css, guide-ui.css, guide.js, guide-map.js(기술 연결 지도)
│  ├─ linux/              리눅스: linux.css, linux.js, linux-viz.js(스캔 뷰포트), linux-mode.js(계열 전환 연출), lab-shell.js(가상 셸 엔진), lab-theatre.js(느린 명령의 연출 계획), lab.js(따라하기 화면·재생)
│  ├─ network/            네트워크: network.css, network.js(서브넷 계산기), network-field.js(배경 그래프)
│  ├─ lab3d/              3D 테스트 페이지: lab3d.css, lab3d.js(구간 내용 SECTIONS, 카메라, d3 그래프)
│  ├─ codetest/           코드 테스트 페이지: codetest.css, codetest.js(연출 엔진·변주·수정 모드), codetest-scenes.js(연출 다섯 가지), codetest-code.js(수정 모드 코드 50개)
│  └─ ai/                 AI 페이지: ai.css, ai.js(실습 여섯 개 LABS, 플랜 표 렌더), ai-memory.js(7장 기억 시뮬레이터), ai-where.js(7장 어디서 도느냐 흐름 `ENVS`, 닿는 범위 표 `REACH`, 원본→환경 그림), ai-token.js(3장 토큰 계산기. `vendor/tokenizer-*.js`를 처음 쓸 때 불러오고, 그 파일은 `npm run build`가 gpt-tokenizer에서 복사해)
├─ data/                  사람이 고치는 데이터 층
│  ├─ sites.js            메인 페이지와 하위 페이지 목록(드롭다운·탭·키워드 페이지가 읽는다)
│  ├─ map-data.js         기술 연결 지도의 노드와 연결
│  ├─ linux-lab.js        리눅스 따라하기 실습(가상 파일, 단계별 명령과 해설)
│  ├─ ai-data.js          AI 페이지 데이터(요금제·기능 표·업데이트 기록·출처). 값이 바뀌면 여기만 고친다
│  ├─ glossary/*.json     용어 사전(network, linux, dev). 용어 추가·수정은 여기
│  └─ generated/          npm run build가 만드는 파일. 직접 고치지 않는다(search-index.js, glossary-data.js)
└─ vendor/                받아 둔 외부 라이브러리(d3)와 폰트(fonts/PretendardVariable.woff2, OFL)
```

- 무엇을 바꾸는지에 따라 층이 나뉜다. 글 수정은 html, 모양 수정은 `assets/`, 목록·용어·지도 수정은 `data/`다.
- 모든 페이지는 `<head>`에서 공용 묶음을 같은 순서로 불러온다(site-ui.css, glossary.css, search-index.js, glossary-data.js, sites.js, site-nav.js, glossary.js). 새 페이지는 기존 페이지의 머리말을 복사해 만들고, 빠지거나 순서가 틀리면 `npm run check`가 알려 준다.
- 사이트 전용 코드는 그 사이트 폴더 안에서만 고치고, 두 사이트 이상이 쓰면 `assets/shared/`로 옮긴다.
- **리눅스 따라하기 실습**: 실습 내용은 `data/linux-lab.js`에서 고쳐. 단계마다 `cmd`(입력할 명령, 계열별이면 `{ deb, rh }`), `say`(설명), `ok`(해설)를 쓰고, 실패해야 정상인 단계는 `fails: true`를 달아. `npm run check`가 모든 단계를 두 계열 모두에서 시뮬레이터로 실행해 성공 여부를 확인해. 새 명령어가 필요하면 `assets/linux/lab-shell.js`에 추가해. 오래 걸리는 명령(apt·dnf·ping)은 `assets/linux/lab-theatre.js`가 "연결 중 → 한 줄씩 → 진행 막대·점 도는 대기" 연출 계획을 만들고 `lab.js`가 재생해(재생 중 Enter·Ctrl+C·Esc는 건너뛰기, 일반 명령은 즉시 출력). 연출은 글자를 바꾸지 않고 시간만 더하며, 새 느린 명령은 theatre의 `SLOW`와 규칙에 추가해. 실습 상태는 메모리에만 있어서 새로고침하면 사라지고, 이 사실은 페이지에 항상 적어 둬. 시뮬레이터에서 성공한 것은 실제 환경에서 마스터가 확인하기 전에는 완료로 표시하지 않아.
- **메인 페이지(루트 `index.html`)**: 맨 처음 열리는 진짜 메인이야. 코드 비가 쏟아지고 마우스 자리에 ASCII 아트 블랙홀(그림자, 광자 고리, 휘어진 빛, 강착 원반)이 떠. 블랙홀 글자는 안정적으로 유지하고, 바탕에 깔린 실제 글자 칸은 세계 좌표에 고정돼 있다가 블랙홀이 가까워지면 칸마다 다른 시점에 하나씩 떨어져 나와 중력과 소용돌이로 서서히 끌려가(삼켜진 자리는 몇 초 뒤 다시 생겨나고, 포인터가 멀어지면 제자리로 돌아가). 코드 비는 그대로 두고 블랙홀 쪽으로 살짝 휘어지기만 해. 이 물리는 `home.js`의 `physics()`에 있어. 클릭·드래그하면 화면 가득한 코드가 완전한 원형 소용돌이로 그 지점에 끝없이 흘러드는데(원판 안에 글자를 면적 균일하게 깔고, 화면 밖 원판 부분에는 유령 글자를 미리 깔아 두어 핵에서 사라진 글자가 바깥에서 다시 들어오니 화면이 비지 않아. 밝기·밀도는 천천히 올려 클릭 순간에 튀지 않고, 처음엔 천천히 갈수록 기하급수로 빨라져. 약 2.6초), 글자가 빠르게 뒤바뀌다가 제목과 선택 카드가 블랙홀에서 변형되며 튀어나와(화면이 끊기지 않게 겹쳐). 선택 카드는 `data/sites.js`로 자동 생성돼. 같은 탭에서 한 번 본 뒤에는 바로 선택 화면으로 가고(`?intro=1`로 다시 봐), 모션 줄이기 설정이면 연출 없이 선택 화면이야. 연출 시간은 `home.js` 맨 위의 `COLLAPSE`, `EMERGE`로 조절해. 개발 중에는 콘솔에서 `__homePreview(0.5)`(0~1 빨려드는 구간), `__homePreview(1.3)`(1~2 튀어나오는 구간)로 원하는 순간을 멈춰 볼 수 있어. 마우스 포인터는 모든 페이지 공용이야(아래 항목). 각 페이지의 드롭다운 맨 위 `메인` 항목이 여기로 돌아와.
- **마우스 포인터**: `assets/shared/cursor.js`·`cursor.css`가 맡아. 화살표는 마스터가 고른 이미지(assets/home/cursor@2x.png를 cursor.css에 base64로 넣어 마스크로 쓰고 테마 색으로 칠함, 끝점이 클릭 지점)고, 마름모 고리와 함께 포인터에 지연 없이 붙어. 이미지를 바꾸면 tools의 make-cursor.js로 PNG를 만든 뒤 cursor.css의 --arrow 값을 새 base64로 바꿔. 색은 페이지의 `--accent`(메인 페이지는 먹색+붉은 고리)를 읽어 테마와 리눅스 계열 전환에 맞춰 바뀌어. 동작: 링크·버튼 확장, 용어 위 `?`, 지도 위 잡기, 누름 수축+파문, 드래그하면 범위 지정 상자로 변신(크기 표시), 로딩과 페이지 이동 중에는 정렬 막대와 알고리즘 이름이 떠올라. 코드에서는 `Cursor.busy(true, '이유')`로 로딩 연출을 켜고 `false`로 꺼. 입력칸 위에서는 기본 글자 커서를 쓰고, 터치 기기에서는 동작하지 않아. 모서리는 각지게 하고 transform·opacity만 움직여. site-nav.js가 자동으로 불러오고 메인 페이지는 index.html이 직접 불러와.
- **페이지 전환 연출**: 다른 메인 페이지(메인·VS Code 공부·리눅스·네트워크·키워드)로 가는 링크를 누르면 `assets/shared/transition.js`가 화면 전체에 코드 글자를 한꺼번에 띄워 난수로 계속 뒤바꾸고, 도착 페이지 색이 서서히 번져(디졸브) 덮어(약 0.31초). 새 페이지는 같은 장막으로 시작해 글자가 무작위로 꺼지고 색이 걷히며 드러나(약 0.38초). 색 번짐은 WAAPI(합성 스레드)라 로딩 중에도 멈추지 않고, 글자는 글자 판에서 찍어 초당 약 24번만 그려. 첫 화면이 그려지기 전에 장막을 올려야 해서 이 파일은 모든 페이지 <head>에서 defer 없이 불러와(`npm run check`가 순서를 검사해). 같은 사이트 안 탭, 새 탭, 해시 이동, 모션 줄이기에서는 쓰지 않아. 시간은 `OUT`, `IN`, `TICK`, 색과 명령 문구는 `THEMES`.
- **3D 테스트(`3d-test.html`)**: 레퍼런스 영상(긴 길 위로 카메라가 날아가는 3D 스크롤)의 구성을 라이브러리 없이 CSS 3D로 따라 한 시험 페이지야. 폰트는 프리텐다드 하나만 써. 첫 장면(세로 큰 글자 + 정보 + d3 관계 그래프)이 스크롤하면 눕고, 입체 글자가 서고, 카메라가 구간(Git·GitHub·VS Code·Linux·Network·Keywords)을 따라 나아가. 구간 내용은 `lab3d.js`의 `SECTIONS`에서 고치고, 기울기·이동은 `view()`에서 transform만 바꿔. 구간 제목은 구간 맨 위에 서 있는 입체 글자고(정면 보기에서는 같은 자리의 평면 제목), 이 페이지는 머리말 메뉴를 숨기고 고정 메뉴바 하나만 항상 보여(body의 data-bar="always"). 구간(또는 왼쪽 목차 항목)을 누르면 그 구간을 정면으로 마주 보는 집중 보기로 날아가고(Esc, 다른 곳 클릭, 스크롤, ←/→로 이어서 이동), 배경 선(고리·점선·속도선)은 스크롤과 시간에 따라 움직이며, 포인터에 따라 장면이 살짝 기울고, 카드는 올려다보면 떠오르고, 첫 장면 그래프 노드는 포인터가 밀어내. 길 끝(마지막 구간 다음)에서는 장면이 다시 평면으로 서서 마무리 페이지(여섯 페이지 링크 표)를 정면으로 보여 줘. 왼쪽 목차의 선은 레일·점·미끄러지는 표시·글자 밑 줄기·카드로 뻗는 곡선 가지가 하나의 SVG로 이어지고(`hudUpdate()`), 집중 보기로 넘어갈 때는 변형 속도(f)에 맞춰 줄기·가지가 페이드아웃, 돌아오면 페이드인과 함께 다시 자라 연결돼. 개발 중에는 콘솔에서 `__lab3dSet(0.45)`, `__lab3dSet(1)`, `__lab3dSet(0.3, 2)`로 원하는 진행도·집중 구간을 멈춰 볼 수 있어. 글자 안 설명창(용어)은 `data-no-gl`로 꺼 뒀어. 레퍼런스의 상표와 문구는 쓰지 않고 이 사이트의 내용으로 채웠어.
- **코드 테스트(`code-test.html`)**: 작업 중인 cmd 화면처럼 보이는 연출 페이지야. 실행 모드는 파이썬 프로그램이 도는 것처럼 계산 결과가 무작위로 쏟아져(손실값 수렴, 피보나치, 소수 개수, 뉴턴법, 몬테카를로 pi, 경사하강, 행렬식, 통계, 심프슨 적분, softmax, gcd, 콜라츠, 정렬 벤치마크, pytest 점, 로그 등. 값은 모두 실제로 계산해서 읽어도 맞아). 한 줄씩 나오다가 이따금 점이 도는 로딩과 진행 막대, 이따금 빠르게 텍스트가 지나가. 클릭하거나 아무 키나 누르면 수정 모드(상태줄 없는 vim 모양)가 되어 키 한 번에 한 글자씩 파이썬 코드가 색칠되며 써지고(줄바꿈 키는 다음 줄 들여쓰기까지 넣음, 의미는 없음, Backspace로 지움), Enter를 누르면 곧바로 다시 실행 연출을 해(상태줄과 안내 문구는 하나도 없이 코드와 줄 번호만 보여). 탭 제목은 영어 Debugging Test야. 실행 모드는 단축키 1~5로 연출을 바꿔(1 수치 계산·학습(epoch 최대 1500), 2 LLM 연구, 3 데이터 분석 에이전트, 4 네트워크 진단, 5 네트워크 보안 관제. 1~5는 실행 모드에서만 먹고, 수정 모드에서는 글자로 쳐져). 한 구간(90~150초)은 같은 설정으로 돌다가 변주 줄(노란 띠, 경보는 붉은 띠)과 함께 설정·생성기 비중·속도를 새로 뽑아 다음 구간을 돌아. 연출 내용은 `codetest-scenes.js`의 시나리오(`gens`, `phase`, `shift`, `spin`, `bar`, `burst`)에서 늘리고, 주소는 문서용·사설 대역만 써. 콘솔에서 `__ct.go(3)`, `__ct.shift()`로 바로 확인해. 화면 줄은 `flex:none`이라 창이 좁아 접혀도 겹치지 않아. 수정 모드 코드는 `codetest-code.js`에 연출마다 10개씩 하드코딩해 두고, 들어올 때마다 지금 연출의 목록에서 하나를 무작위로(직전 것 제외) 골라 창 제목에 그 파일 이름(vim lora.py 등)을 보여. 다 쓰면 같은 연출의 다른 조각이 이어져. 이 파일은 JS 템플릿 문자열이라 역슬래시와 달러+중괄호를 쓰지 마. 연출 몰입을 위해 이 페이지는 메뉴를 전부 숨겨(머리말 메뉴도 고정 메뉴바도 없음. 나갈 때는 브라우저 뒤로 가기).
- **AI 페이지(`ai.html`)**: Claude Code와 Codex 가이드야. 설치와 첫 실행(공식 GitHub·설치 문서 링크, `#inst`의 운영체제 전환과 복사 버튼은 `ai.js` 끝에 있어. 명령 상자에는 `data-no-gl`을 붙여 용어 밑줄을 막아) → 기초(에이전트 루프, 토큰 계산기, 좋은 요청 네 요소) → 두 도구의 동작 방식 비교 → 실무 사용법 → 심화(컨텍스트, 기억, 하네스) → 실습 여섯 개 → 플랜별 기능 → 업데이트 기록 → 출처 순서고, 새 메인 페이지로 `data/sites.js`에 `ai`로 등록했어(색은 Claude 점토 주황, Codex 청록). 실습은 모두 이 페이지 안의 시뮬레이션이고 저장하지 않아: 1) 지시문 규칙 켜고 끄기 2) 컨텍스트 채우기와 /compact·/clear 3) 권한 모드 비교 4) 훅과 검증 재생 5) 서브에이전트로 컨텍스트 절약 6) claude -p, codex exec 명령 만들기. 각 실습은 "일어난 일 / 달라진 점 / 왜 그런가"를 같이 보여 줘. 요금제와 업데이트는 `data/ai-data.js`에 있고, 공식 페이지에서 읽히지 않은 칸은 `?`로 둬. 이 값은 자주 바뀌니 `asof`와 `snap`(버전)을 같이 고쳐. 7장 기억은 `assets/ai/ai-memory.js`의 시뮬레이터(도구 4개(Claude Code 로컬·클라우드, Codex 로컬·Cloud) × 상황 5개, 파일이 범위 상자에서 컨텍스트 창으로 날아감)로 보여 줘. 파일 목록은 `SOURCES`, 상황별 판정은 `rule()`, 정리 문장은 `SUMMARY`에서 고쳐. 용어(하네스, 컨텍스트, 에이전트, 서브에이전트, 훅, 샌드박스, 스킬, 자동 메모리)는 `data/glossary/dev.json`에 있어.
